## [2.8.3] - 2026-09-28

2.8 cut 4 — **the skill "activation gate" gets an input surface** (刀 B, touches `src/`; a *non-content* cut ⇒ hard anchor = B10 verbatim, **but** gates carry gameplay meaning ⇒ all three gates of the gameplay-knife protocol fired, including the independent recompute). Since v2.7.3 the engine could *evaluate* a gate; no user could *write* one. This cut connects that pipe end to end and, in doing so, establishes the project's strictest rule about reading what the user typed.

- **Requirements, settled before code** (user's ruling 2026-09-27, three forks resolved 2026-09-28): (a) **plan A** — Excel and the editor header hold only **base values**; a panel value = base + skill bonus is **derived by the engine**, so there is no "hand-type the panel number" surface (recorded as policy this round; the derivation channel belongs to a future "value change + duration" cut); (b) **plan A + line break** — several "if/then" branches in one cell are separated **by the user's own newline**, and the parser splits on newline; (c) "my player's hand count" = the hand count of **the player seat that owns the skill**, with the standing declaration **"in my game only players hold cards — generals never do"** (promoted into §4 frozen rules). Carried-over wording: gates attach **only to a specific effect**, "choose one of" is out of scope this round, and **in Excel a gate is one column of plain-language text with conditions separated by 、 or ,**.
- **Four places wired**: data layer `SkillEffect.conditions?` (the type lives in `src/data/generals.ts`; `src/skills/dataTypes.ts` only re-exports it, keeping the skills→data arrow one-way); text↔structure translation = new `src/skills/skillGateText.ts` (one grammar `[subject?] metric op (metric|number)`, `parseGateText() → {conditions, unknown}`, `gateConditionsToText()`, `GATE_SYNTAX_HINT`); compiler `src/skills/skillCompiler.ts` passes each effect's conditions **straight through** (zero evaluation at compile time — evaluation still lives in exactly one file, `skillConditions.ts`, untouched); the input surface = one "🚪 发动门槛" card per effect (new `src/components/skillEditor/GateEditor.tsx`) **plus the Excel effect group growing to a 7th column "门槛"** (v1=3 / v2=6 / v3=7, `detectEffectGroupWidth` probes the header instead of counting, export is always 7 wide).
- **The most important design decision in this cut: a gate must never be silently misread.** `parseEffectGroup` no longer returns a bag of fields but `{fields, gateUnknown, orphanGate?, triggerUnreadable?}` — **every unreadable fragment is reported, none dropped**, and gate-text and trigger-text warnings share one channel (`parseWarnings`). After import the editor shows a **persistent** panel head: 「⚠ 有 N 处没看懂，这些内容没有被记下来（技能会照「没写」那样发动）」, dismissed only by an explicit click, while the input box echoes live "看懂了：A 且 B" versus "没看懂（这些条件不会生效）：「…」". Rationale: a gate is the thing that can **stop a skill firing** — a missed condition means the user believes there is a protection that is not there, which is the one input surface in this project that may not fake success.
- **"Choose one of" × gate = the whole group refuses to compile** (`CONDITION_CHOICE_UNSUPPORTED`): one choice definition has a single `conditions` slot, so per-effect gates are structurally inexpressible — the group is withheld and reported per line, rather than "freeing" the conditions that look unconditional (never invent gameplay). A lone effect still compiles as an independent definition with an unchanged id shape.
- **A real bug, found only because gate work made "my trigger won't save" the most common complaint**: the second input surface touched is `TriggerEditor`'s "照这个填" box, now sharing a **strict reader** `readTriggerCell(s)` with the Excel 触发 column — a string is accepted only if it **round-trips back to exactly itself**. The old `strToTrigger` matched only the main name, so 「受到伤害后→攻击」 was accepted with its subtype **silently discarded**, i.e. the user's "attack damage only" became "all damage" — the worst shape of "pretending to understand". Both the quick-fill box and the import path now use the strict reading, refuse cleanly, list every accepted spelling, and a test nails that **every dropdown option must pass it** (so the strictness can never lock out the editor's own vocabulary).
- **Honest leftovers, registered not fixed**: a gate written on a description-only effect gates nothing (the compiler still skips that effect as `NO_RUNTIME_PAYLOAD`, and no extra hint was added — the same fact said twice is noise); unreadable gate text is not archived, so re-export writes 「无」 there (the alternative witnesses are the per-line report at import time and the live red block; the user's own `.xlsx` always still holds the original). And **an effect group that contains only a gate creates no effect** — this replaced the original design ("a gate column alone counts as a group"), which in practice produced an effect with conditions and nothing to resolve; refusing and saying so won.
- **Tests 579/62 → 617/64**: new `skillGateText.test.ts` (14 — including the suspicion list of reversible wordings: 不少于/不超过, Chinese numerals, metric-on-both-sides, half-clauses landing in `unknown`, trailing quantifier tails 「数量/数目/数/量」 and filler 「为/是」 not blocking, global metrics ignoring a written subject) + new `skillExcelParsers.test.ts` (8) + `skillExcelFormat.test.ts` effect-group section rewritten for v3 with the strict reader + 5 compiler passthrough cases + **4 component-level cases** in `SkillEditor.runtime.test.tsx` + **1 mock-free real-engine closed loop** in `skillPipeline.test.ts` (gate text → `parseGateText` → a real `GameEngine`, two attacks: draw at hand=1, nothing at hand=2). ## [2.8.0] - 2026-09-27

2.8 mainline **cut 1 — general identity lock (a *content* cut: the standard-mode AI direct pool is locked too, so the baseline anchor moves B9→B10 — per user decision D3, rolling the AI-side lock back to preserve B9 is forbidden)**: cards with the same identity are dealt once per room and the deal itself is the lock.

- **Six-rule spec, contract-first** (`PROJECT_ARCH_MAP.md` §F identity-lock table written before code): ① same-name generals share one *identity*; identity × faction = one concrete card type. ② **dealt = locked** — once a candidate card reaches a seat it is that seat's, and a card never drafted still **sinks** the identity for the rest of the room. ③ within one seat the main surface and the 群 surface dodge each other's identities; 群 same-name is room-global; two *different* players holding the same name under *different* factions stays legal. ④ the lock is independent of survival — death/discard/return never releases it — and there is **no retroactive rewrite**: old saves where same-identity cards coexist only show a warning, while a *new* conflict at assembly time **rejects the whole batch with an explicit reason**. ⑤ identity `'DIY'` never locks; a **blank identity means no identity, no lock**; ⑥ same lock keys dedupe inside one seat's surface too.
- **Data layer**: `General.identity?: string`, resolvable **only** through new `src/domain/identity.ts` (fallback chain: undefined → the general's own name; blank → null/no lock; `DIY_IDENTITY` exempt; lock key = `(identity, faction)`). Legacy localStorage needs zero migration; Excel keeps its pinned six columns (decision D1 — no seventh column).
- **Draft chain** (`buildDraftCandidates` gains the dealt ledger + editor-merged pool params): all lock filters sit **before** each shuffle and consume zero randomness; the store tracks a `draftDistributed` ledger of everything dealt to earlier seats (drafted or sunk) — a B-class presentation mirror verified **not** to enter canonical `EngineState`.
- **AI direct pool** (`ai/matchSetup`): same lock on the seeded path; explicit seat lineups that collide throw `身份锁拒绝整批装配：…` instead of silently filtering (red line: validators may reject, never invent a second state path).
